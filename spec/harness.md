# Harness contract

`phoenix.harness.yaml` sits in the harness repository. `run` says how to run the harness in one of three forms: a `command` with its `output`; for a long-lived server harness, `serve`, `ready` and `submit`; or `resume`, which means the harness is put back in a moment by resuming the moment's own session file with its recipe. The first two forms may give `build` and `image`. A harness that doesn't resume names its `endpoints`: `model.env` is the environment variable the harness reads its LLM's base URL from, and `mcp` says where MCP servers are configured (`file` and `format`). A replay sets that variable to the LLM URL in the replay settings and lets the box reach that host directly; nothing from Phoenix sits in between. `editable` lists the globs of paths an outside agent may change.
